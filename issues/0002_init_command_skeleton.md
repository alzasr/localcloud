# 0002 — Init command skeleton

## Суть задачи

Работа с `localcloud` начинается с создания локального облачного окружения,
но сейчас в интерфейсе нет команды, с которой пользователь мог бы это начать:
доступны только справка и версия.

Нужна болванка команды `init`: она должна быть зарегистрирована в интерфейсе,
объяснять своё назначение и необязательный каталог, аккуратно проверять ввод
и честно сообщать, что создание окружения ещё не реализовано. Болванка
фиксирует контракт команды, чтобы наполнять её реализацией отдельными шагами.

## Критерии готовности

- [x] `localcloud init` распознаётся, принимает необязательный каталог и сообщает, что создание окружения пока не реализовано.
- [x] `localcloud init` завершается ненулевым кодом возврата, чтобы заглушка не выглядела успехом.
- [x] `localcloud help init` и `localcloud init --help` показывают назначение, синтаксис и аргументы команды.
- [x] Лишние аргументы и пустой каталог отклоняются с понятным сообщением и кодом возврата ошибки использования.
- [x] `localcloud help` перечисляет `init`, а README описывает новую команду.
- [x] Поведение закреплено автотестами; тесты, статические проверки и сборка проходят.

## Результат

Болванка команды `init` добавлена: команда зарегистрирована в интерфейсе,
принимает необязательный каталог (по умолчанию текущий), поддерживает
`-h`/`--help`, отклоняет лишние аргументы и пустой каталог с кодом возврата 2
и сообщает, что создание окружения ещё не реализовано, завершаясь с кодом 1.

`localcloud help init` и `localcloud init --help` описывают назначение,
синтаксис, аргумент и флаги; `localcloud help` перечисляет новую команду,
README обновлён примером и пояснением.

Проверено: табличные тесты и отдельный тест на точный текст заглушки,
`go test ./...`, `go vet ./...`, сборка и ручной прогон `init`, `init --help`,
`init a b` — поведение совпадает с ожидаемым.
